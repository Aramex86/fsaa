Roadmap and status

FSAA is young and the docs say so. Everything below is either shipped, or explicitly planned with a phase.

Phases

Phase 0
Methodology + docs siteLayers frozen, graduation pattern written, this site shipped as the reference.
Done
Phase 1
Reference repository + indexationPublic methodology repo (fsaa) with honest README + CONTRIBUTING; docs site indexed (robots, sitemap, GSC).
Done
Phase 2
Boilerplate — Next.js + Vite templatesfsaa-next (Next.js 15 App Router) + fsaa-vite (Vite 7 + react-router) — two template repos. Same layers, AGENTS.md drift-check, ESLint-enforced boundaries, Projects/Orders example inside both.
Done
Phase 3
CLI — npx fsaa initScaffold (npx fsaa init), slice generator (fsaa g), standalone eslint-plugin-fsaa — plus an agent skill that teaches AI coding agents where UI goes, and fsaa audit for boundary drift in existing codebases.
In progress
Phase 4
Community feedback loopCase studies from adopters; rules only change with evidence.
Planned
✔

Used in production on an internal financial accounting tool with real daily users (managers, director, accounting — and the structure survived two feature teams).

Known gaps

Honest limitations and their plans
Known gapPlan
Boilerplate ships as a Git template (clone-and-rename), not an npm CLI yet.Phase 3: npx fsaa init (asks next/vite) + slice generator.
Server-components recipes for pages/entities are thin.Document RSC boundaries per layer on the architecture page.
Slice scaffolding is manual; boundaries enforced by bundled ESLint config.Phase 3: slice generator + standalone eslint-plugin-fsaa.
One production case study (internal tool); more needed.Phase 4: adopter case studies on this site.

Contribute

The methodology docs are versioned with the site. Disagree with a rule? Bring a case study — rules change with evidence, not opinions.
