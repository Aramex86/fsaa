Architecture — layers and boundaries

Five layers on one strict direction of imports. Everything else in FSAA follows from this stack.

Layer stack

The stack is small on purpose: five layers instead of FSD's seven, because the widgets layer is gone and its content lives inside features.

Rule

The widgets layer is removed by design. If a block is big, it is a feature; if it is generic, it belongs to shared/ui. There is no third home.

Import rules

Four rules, in priority order:

  1. A layer imports only layers below it: app → pages → features → entities → shared.
  2. Cross-feature imports go through public APIs only, never deep into another feature.
  3. Within a layer, features do not import each other; extract to entities when needed.
  4. shared imports nothing from the project layers — it is the ground truth of the stack.

Where Atomic Design lives

Scope

Atomic vocabulary is used only inside shared/ui. Features may have "big" and "small" components — nobody grades them by size.

Atomic tiers inside shared/ui
atomsButton, Chip, Pill, CopyButton — generic action control and labels
moleculesCallout, Card, DataTable, PageHeader — composed from atoms
organismstier removed — either a shared molecule or a feature ui component
Rule

Feature ui/ stays flat. Do not create atoms/molecules folders inside a feature — promote to shared only via the graduation pattern.

Split

Molecules shared between features get an export-level split: one file per export, a barrel at the folder root, no cross-imports between molecule folders.
